## Crossref Architecture

```text
DiscoveryProvider → CrossrefDiscoveryProvider → Crossref REST API
```

The platform sees only `DiscoveryResult` / `SourceItem` / `FetchResult` /
`NormalizedSourceItem` / typed `DiscoveryError` — never a raw Crossref response.
Only whitelisted source fields (`crossrefType`, `crossrefMember`, `crossrefScore`)
survive on `SourceItem.raw`. An architecture guard proves no Crossref-specific
code leaks into the generic contracts, `packages/domain/database/ai`, or
`apps/web`.

## Source Descriptor

`CROSSREF_SOURCE_DESCRIPTOR`: host-pinned `allowedHosts: ["api.crossref.org"]`,
`requireHttps: true`, `allowLocalNetwork: false`, 8 s timeout, 5 MiB size cap,
`maxItemsPerRequest: 100`, `maxCandidatesPerRun: 1000`, conservative
`rateLimit {1 rps, burst 2}` — the caps are WiseEvidence's own and **REQUIRE LIVE
VERIFICATION** of Crossref's actual current limits. No base URL is accepted from
callers; the origin is a module constant.

## HTTP Security

Injected `fetch` (never an ambient global); HTTPS only; timeout via
AbortController; response-size cap via streamed reader; redirects rejected
(`redirect: "error"`); content-type validated as JSON; every request URL routed
through `assertUrlAllowed` (defense in depth). Tested: arbitrary host rejected,
http rejected, loopback rejected, blocked redirect fails closed, oversized
rejected, non-JSON/invalid-JSON/wrong-shape rejected, and secrets never appear in
errors.

## Metadata Normalization

Untrusted Crossref fields are length-capped/sanitized (control chars stripped,
markup reduced to text, URLs validated); the generic `normalizeSourceItem` then
canonicalises. No outcome/quality/criticism/efficacy is ever produced.

## DOI Handling

`normalizeDoi`/`toCanonicalDoi` from `@wise-evidence/domain`. Valid, missing,
malformed, and unusually-cased DOIs are handled; the raw DOI is preserved for
provenance; one bad DOI never crashes the run (the item is surfaced, and
normalization decides usefulness).

## Provenance

Every normalized item traces to source key, source id (canonical DOI), source
URL, canonical DOI, discovery/fetch timestamps (injected clock in tests),
connector version `crossref-discovery/1`, and a SHA-256 raw-payload hash. No full
text is stored.

## Error Handling

Timeout → `TIMEOUT`; blocked redirect / connection failure → `SOURCE_UNAVAILABLE`;
429 → `RATE_LIMITED` (+ Retry-After in safe detail); 404 / other 4xx / 5xx →
`SOURCE_UNAVAILABLE`; non-JSON / oversized / invalid-JSON / wrong-shape →
`MALFORMED_RESPONSE`; host-policy violation → `FORBIDDEN_SOURCE`; missing query
and no DOI → `INVALID_IDENTIFIER`. Messages/detail carry no secrets or headers.

## Rate Limiting

Enforced via the descriptor's caps; **no retry loop** in the connector (one
request per operation). Retry/backoff/Retry-After honouring and scheduling are
deferred to the M7.3 orchestrator. Crossref's real limits are **REQUIRES LIVE
VERIFICATION**.
