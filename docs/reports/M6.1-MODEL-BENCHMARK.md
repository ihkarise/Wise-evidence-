# WiseEvidence M6.1 Model Benchmark

## Date

2026-08-24.

## Purpose

Determine which currently available OpenRouter model gives the best
quality + structured-output reliability + cost + latency for WiseEvidence's six
enrichment tasks — the **cheapest model that is reliable enough**, not the most
powerful. Engineering model-selection only; **not** a scientific evidence
judgment, and not biased toward any homeopathy conclusion.

  `recentRelayFailures: [{ kind: "connect_rejected", detail: "gateway answered

  The proxy `noProxy` allowlist contains only Anthropic hosts + package registries
  (npm/pypi/crates/go); `openrouter.ai` is not permitted. The proxy README states:
  *"The destination host is not allowed by your organization's egress policy for
  this session. Do not retry or route around it — report the blocked host."*
- **No OpenRouter credential is configured** (`AI_BASE_URL` / `AI_API_KEY` unset;
  no `.env`). Even with a key, the egress policy denies the connection.

Because the OpenRouter catalogue itself is unreachable, candidate model **slugs
could not be verified** and **current pricing could not be confirmed** — both are
required preconditions of this benchmark. Nothing downstream can be produced
honestly here.

### What was prepared (so the benchmark is one command away when egress is allowed)

A gated, mock-validated **multi-model benchmark harness** —
`packages/database/src/m6-1-benchmark.test.ts` — using the **existing**
`OpenAICompatibleProvider` and `ai_job`/`ai_result` infrastructure. **No** new
provider abstraction, **no** adapter change, **no** schema change, **no** queue,
**no** background jobs. It loops the configured model slugs over the six tasks on
the DEMO study (same source/prompt/prompt-version/settings; the only variable is
the model), and records per model × task: latency, reliability (with a single,
**marked** retry for transient transport errors), provider-reported token usage,
structured-output validity, and cost from operator-supplied per-model pricing. It
bypasses the cache while measuring inference, then verifies M6 cache behaviour
separately. Offline (mock) validation confirmed the matrix, per-model summary,
projections, and cache-HIT logic, and confirmed it reports `UNAVAILABLE`/`n/a`
(never `0`) when real usage/pricing is absent.

## Benchmark Method

Same input, prompt, prompt-version, and request settings for every model; only
the model varies (`AI_BENCH_MODELS`). Existing M6 prompt-injection protection is
retained — research text stays wrapped as `UNTRUSTED_RESEARCH_DATA`; system
instructions are unchanged and not weakened. Structured output uses the existing
adapter's `response_format: { type: "json_object" }` (see *Structured Output*).
Validation uses the existing M6 schemas; validation is never weakened to make a
model pass.

## Six Tasks

## Structured Output

The existing `OpenAICompatibleProvider` requests `response_format:
{ type: "json_object" }` (JSON-object mode), then validates against the M6
schemas. It does **not** send a strict per-task `json_schema` — adding that would
modify the adapter, which this benchmark is instructed not to do. Per model the
harness records `VALID` / `INVALID` / `ERROR`; a model that cannot return
schema-valid JSON is recorded as failing, not accommodated. (Strict
`json_schema` response-format is a possible future adapter enhancement, out of
scope for this benchmark.)
