## 1. Purpose

Add **PubMed / NCBI** as the third research discovery source, after Crossref (C1)
and Europe PMC (C2), completing the priority order **Crossref → Europe PMC →
PubMed**. PubMed is a **discovery source only**: it finds bibliographic metadata
and produces provider-neutral discovery objects that flow through the EXISTING
normalize → dedup → human-review pipeline. It never decides whether research is
valid, never publishes, never creates an accepted study, and never invokes AI.

## 3. PubMed API approach (Option A, JSON only)

Two structured JSON endpoints, nothing else:

| Step | Endpoint | Purpose |
|---|---|---|
| 1 | `GET …/esearch.fcgi?db=pubmed&term=…&retmode=json&retstart=&retmax=` | term → a page of PMIDs (+ total `count`) |
| 2 | `GET …/esummary.fcgi?db=pubmed&id=…&retmode=json&version=2.0` | PMIDs → bibliographic metadata |

`discover()` performs both calls per page; `fetch(ref)` is a single ESummary call
for one PMID. The orchestrator counts **one** request per `discover()`/`fetch()`;
the two HTTP calls of a page stay inside the connector.

### JSON-only decision (no XML)

PubMed abstracts require the XML EFetch endpoint. M7.7 deliberately **excludes**
XML entirely:

- ❌ No XML parser (a boundary test asserts none is imported)
- ❌ No abstract scraping / retrieval
- ❌ No full-text retrieval; `efetch.fcgi` is never referenced

The descriptor declares `capabilities.providesAbstracts = false`; Crossref /
Europe PMC provide abstracts for the same research record where appropriate.

## 4. Identifiers & pagination

- **PMID is PubMed's stable source id** — a record with **no DOI is still fully
  discoverable** because the PMID is always present and is used as the candidate
  identity (`source_stable_id`).
- **DOI** is taken from ESummary `articleids` (`idtype: "doi"`), with a fallback
  parse of `elocationid` (`"doi: 10.…"`), and canonicalised via
  `@wise-evidence/domain` — the same DOI normalization used platform-wide.
- **PMCID** is taken from `articleids` (`pmc`/`pmcid`) and normalised to a
  `PMC…`-prefixed value. PMID/PMCID reuse existing identifier conventions; **no new
  identifier type was invented.**
- **Pagination** reuses the existing opaque-cursor model, encoding PubMed's
  `retstart`; `retmax` is the clamped page size. The connector advances only while
  a full page returned AND the next offset stays below the reported `count`, so a
  run is always bounded and respects the orchestrator budget.

## 5. Security posture (mirrors M7.2/M7.6, verbatim machinery)

- **HTTPS only, host-PINNED** to `eutils.ncbi.nlm.nih.gov` via a module constant;
  every request URL is re-gated through `assertUrlAllowed`. The host is never taken
  from a caller-supplied base URL.
- **Injected fetch** (never an ambient global) — deterministic, network-free tests.
- **Timeout-bounded** (AbortController), **response-size-bounded** (streamed cap),
  **redirects rejected** (`redirect: "error"`), **content-type validated** as JSON,
  **JSON structure validated** before use.
- **Untrusted metadata**: every field length-capped/sanitized; markup never
  rendered; DOIs canonicalised.
- **Query/operator-injection hardening**: free-text queries are stripped of PubMed
  field tags (`[Title]`, …) and boolean operators (AND/OR/NOT) before entering the
  `term`; PMID clauses are digit-validated, DOI clauses quote-escaped.
- **No secrets**: the public E-utilities are used **without an API key**. NCBI's
  optional `api_key`/`tool`/`email` params are intentionally NOT added. A configured
  contact email appears only in a polite `User-Agent`, never in the URL. Errors are
  redacted and never leak secrets (test-covered).

## 6. Rate-limit handling

NCBI's public no-key limit (~3 req/s) is **not verifiable from this
egress-restricted environment** → **🟡 LIVE VERIFICATION PENDING**. The descriptor
uses a conservative application cap (`requestsPerSecond: 1`, `burst: 2`) that the
connector always enforces regardless of NCBI's actual limits. The connector adds no
scheduler/worker/retry/concurrency of its own; bounded retries, `Retry-After`
honouring, and scheduling remain the M7.3 orchestrator's job. A 429 is surfaced as a
typed `RATE_LIMITED` error with any Retry-After in safe detail. No unverified
assumption was recorded as a test result.

## 7. Error handling

Transport/HTTP failures map onto the M7.1 typed errors: timeout → `TIMEOUT`;
blocked redirect / connection failure → `SOURCE_UNAVAILABLE`; 429 → `RATE_LIMITED`;
4xx/5xx → `SOURCE_UNAVAILABLE`; non-JSON, oversized, invalid JSON, or wrong
structure → `MALFORMED_RESPONSE`. A well-formed empty ESearch idlist is a **terminal
page**, not an error; a per-record ESummary `error` string is **skipped**, not
surfaced; an unbounded request (no query, PMID, or DOI) is refused
(`INVALID_IDENTIFIER`).

## 8. Boundaries preserved (test-covered)

- **AI ≠ authority / not used:** the connector imports no AI SDK and makes no AI
  call; discovery is metadata retrieval only.
- **Human review is the safety boundary:** DISCOVER → CANDIDATE → DEDUP → HUMAN
  REVIEW. No auto-accept, auto-publish, auto-merge, or auto-delete.
- **DUPLICATE ≠ DELETE / Study ≠ Publication:** a record whose DOI already belongs
  to a known study is flagged `DUPLICATE_CANDIDATE` for human review, never merged,
  deleted, or published (integration-test-covered).
- **No canonical writes:** discovery imports no `@wise-evidence/database`, writes
  nothing canonical, and does not leak PubMed-specific code into the generic
  contracts (`boundary.test.ts`).
- Registry stays selection-based — no `if source === "pubmed"` anywhere.

## 9. Database & migrations

## 11. Limitations

- No abstracts from PubMed (JSON-only, by design) — abstracts come from
  Crossref/Europe PMC for the same record.
- Live rate-limit behaviour and live endpoint shape are unverified from this
  environment (PENDING).
- Date parsing relies on ESummary `sortpubdate`/`epubdate`/`pubdate`; unusual date
  encodings degrade to year-only or null rather than guessing.
