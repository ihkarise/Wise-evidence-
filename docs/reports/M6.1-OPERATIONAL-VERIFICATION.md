## Security (Step 9)

- **API key never reaches the browser:** `AI_*` are read only in
  `apps/web/src/server/ai.ts` (SSR) and the harness; no `PUBLIC_AI_*` exists;
  grep confirms no client references.
- **AI endpoint server-side + staff-gated:** `/api/admin/research/[id]/enrich` is
  `prerender = false` and returns 401 without `locals.staff` (middleware).
- **Untrusted content delimited:** research text is wrapped by
  `renderUntrustedInput` (`<<<UNTRUSTED_RESEARCH_DATA … >>>`), control-stripped, and
  fence/role-prefix-defused; the system guard tells the model to treat the block as
  data.
- **External URLs not auto-fetched:** the adapter only POSTs to the configured base
  URL; it never follows URLs found in research text (no web-fetch tool).
- **AI cannot change publication state / bypass RLS / change roles:** AI writes only
  `ai_job`/`ai_result` under RLS; publish stays ADMIN-only and fail-closed.
- **secret scan:** run after the change — clean (see below).

## Copyright / Data Minimization (Step 10)

- **Sent to the provider:** title, human summary, study type, subject, journal,
  year, and abstract *only where already stored/permitted* — nothing else.
- **NOT sent:** full-paper text (never), PDFs, publisher HTML.
- **Stored:** the AI suggestion (`ai_result.output`) + an `input_hash` (a SHA-256
  hash, **not** a copy of the input). No extra copy of source material is created.
