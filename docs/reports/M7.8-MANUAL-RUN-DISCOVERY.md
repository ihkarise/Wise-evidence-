## 1. Why this milestone exists

The discovery stack was fully built and end-to-end tested before M7.8:

```text
Crossref → Europe PMC → PubMed → normalization → conservative dedup → candidate storage → human review
```

…but **nothing in the running application called it**. `runDiscovery` (M7.3) and the
database adapters `DatabaseDiscoveryStore` / `DatabaseStudyIndex` (M7.4A) were only
reachable from tests. There was no runtime web endpoint or button for a staff member
to start discovery.

M7.8 adds exactly one missing piece: a **safe manual switch** that invokes the
**existing** engine. It proves the path

```text
MANUAL RUN → REAL DISCOVERY → DATABASE → CANDIDATE → HUMAN REVIEW
```

so that scheduling can later be considered on evidence — but scheduling is **not**
part of M7.8 and is **not authorized**.

## 4. Trust boundary (client is never trusted)

The request carries only a **provider selection** and an **optional bounded query**.
Everything else is server-controlled:

- **Identity + role** — from `locals.actor` (server session). Staff enforced four
  times: middleware (401/403 on `/api/admin/*`) → `requireStaff` in the service →
  `requireStaff` in `DatabaseDiscoveryStore` → non-staff `DiscoveryActor` refused in
  the orchestrator. A PUBLIC actor is refused before any `import_job` is created.
- **Provider** — validated against `MANUAL_DISCOVERY_PROVIDERS` (MOCK · CROSSREF ·
  EUROPE_PMC · PUBMED). A URL, host, or unknown string is rejected `invalid-input`.
- **Budget** — never client-supplied; the conservative `DEFAULT_BUDGET` applies,
  each field hard-clamped. A run can never be unbounded.
- **Host / base URL** — pinned inside each connector; no generic URL fetch exists.
- **Persistence / dedup / study identity** — decided by the unchanged orchestrator
  and adapters.
